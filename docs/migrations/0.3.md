# Migrating from 0.2 to 0.3

Argui 0.3 adds local typed widget handlers and the renderer-independent
`argui-testing` crate. The low-level listener and behavior/action layers remain
supported; migrate code where a reaction is naturally local.

## Buttons

Before:

```rust,ignore
Button::new("save", "Save", theme.button()).build().on(
    cx.listener(EventType::Click, |editor, event, cx| {
        if event.target_key() == Some("save") {
            editor.save();
            cx.notify();
        }
    }),
)
```

After:

```rust,ignore
Button::new("save", "Save", theme.button())
    .on_click(cx.callback(|editor| editor.save()))
    .build()
```

Use `event_handler` instead of `callback` when the operation needs the raw event
or must control propagation. It does not invalidate automatically.

## Forms

Before, applications matched `UiEventKind::TextChanged`, `Submitted`, and click
targets. After, bind typed values directly:

```rust,ignore
Input::new("name", &self.name, "Name", theme.input())
    .on_input(cx.input_callback(|form, value| form.name = value))
    .on_submit(cx.submit_callback(|form, _| form.save()))
    .build()

Checkbox::new("public", "Public", self.public)
    .on_change(cx.value_callback(|form, value| form.public = value))
    .build(&theme)
```

## Overlays

Keep open state controlled and consume the requested boolean:

```rust,ignore
Dialog::new("settings", "Settings", self.open, trigger, content)
    .on_open_change(cx.value_callback(|app, open| app.open = open))
    .on_dismiss(cx.callback(|app| app.record_dismissal()))
    .build(&theme)
```

Nested overlays use target-only direct delivery, so a child dismissal does not
accidentally fire the parent's direct callback.

## Complex controlled widgets

Simple selection can move to `on_select`. Retain the typed action reducer when
the application needs modifier/range selection, focus requests, validation,
editing, sorting, resizing, submenu intent, or another multi-effect response.
There is no deprecated duplicate API: `Context::listener`, `Element::on`, and
all behavior/action types are still the advanced layer.

## Testing

Add `argui-testing = "0.3.0"` as a development dependency. `TestApp::click`
uses real layout and pointer hit testing; `accessibility_action` is a separate
semantic path. `advance` drives animations and native test-task time without
sleeping. `TestWindows` covers independent presentations of shared state.

## Mobile Web text input

Focused WebAssembly `Input` and `TextArea` widgets now focus their mirrored HTML
control on touch-capable browsers. This opens the Android and iOS virtual
keyboard while keeping Argui's retained focus and canvas rendering in sync; no
application-side workaround is required.

## Global shortcuts

Applications can request typed global shortcuts through
`ApplicationConfig::with_global_shortcut`. Windows, macOS, and Linux X11 use
native registration; Linux Wayland uses the XDG Global Shortcuts portal and
may display a one-time approval dialog. A Wayland host package must install a
`.desktop` file matching `ApplicationIdentity::linux_application_id()` so the
portal can associate permissions with the application.

## Accessibility UI zoom

Argui 0.3 enables runtime-owned UI zoom by default. Desktop, hardware-keyboard,
and WebAssembly hosts use `Ctrl`/`Command` with `+`, `-`, `0`, or the wheel;
trackpad and touch hosts can pinch. The active value is available as
`WindowEnvironment::ui_zoom` and is synchronized across application windows.

Applications that already own those gestures can preserve their previous input
behavior explicitly:

```rust,ignore
use argui::platform::UiZoomConfig;

let config = ApplicationConfig::new(identity, window)
    .with_ui_zoom(UiZoomConfig::disabled());
```

## Imports and feature profiles

`argui::prelude` exports the common runtime, element, handler, theme, length,
and application configuration types. Widgets stay under `widgets` to avoid
name collisions. Existing granular flags remain unchanged.

- `basic`: tasks plus common form, selection, and overlay widgets.
- `desktop`: `basic` plus native popups, file picking, global shortcuts, tray, backdrops, and updater.
- `web`: `basic` plus WebView/browser embedding support.

Applications optimizing dependency count or binary size can continue selecting
individual `widget-*` features.
