# Localization

`argui-i18n` turns embedded [Fluent](https://projectfluent.org/) resources into
localized strings for ordinary Argui elements and widget labels. It handles
BCP-47 locale negotiation, variables, plurals, compound-message attributes,
per-message fallback, and writing direction without depending on the renderer,
runtime, or widgets.

Enable the optional `i18n` facade feature to use `argui::i18n`:

```toml
[dependencies]
argui = { version = "0.3.2", features = ["i18n"] }
```

Applications using the narrow crate can depend on `argui-i18n` directly.
The Widget Gallery's **Internationalization** example runs the same API with
English, French and Arabic catalogs, including plural, fallback and RTL states.

## Build the catalogs

Keep one or more `.ftl` resources per locale. `include_str!` embeds them in both
native and WebAssembly builds and avoids target-specific file lookup:

```ftl
# locales/en-US/main.ftl
welcome = Welcome, { $name }!
inbox = { $count ->
    [one] One message
   *[other] { $count } messages
}
save-dialog = Save your changes?
    .confirm = Save
    .cancel = Cancel
```

```rust
use argui::i18n::{Catalog, Localizer, langid};

let english = Catalog::from_resources(
    langid!("en-US"),
    [
        include_str!("locales/en-US/main.ftl"),
        include_str!("locales/en-US/settings.ftl"),
    ],
)?;
let french = Catalog::parse(
    langid!("fr"),
    include_str!("locales/fr/main.ftl"),
)?;
let mut localizer = Localizer::new(langid!("en-US"), [english, french])?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

Catalog construction reports Fluent syntax and duplicate identifiers before the
application starts rendering. `Localizer::new` also rejects duplicate locales
and a fallback locale with no catalog.

## Select and format

Pass the user's language preferences in priority order. Negotiation handles
regional variants, so `fr-CA` can select an available `fr` catalog. The declared
fallback is always last in the lookup chain. A message or attribute absent from
the selected catalog is read from the next catalog:

```rust
# use argui::i18n::{Catalog, FluentArgs, Localizer, langid};
# let english = Catalog::parse(langid!("en-US"), "welcome = Welcome, { $name }!")?;
# let french = Catalog::parse(langid!("fr"), "welcome = Bienvenue, { $name } !")?;
# let mut localizer = Localizer::new(langid!("en-US"), [english, french])?;
localizer.select([langid!("fr-CA"), langid!("en-US")]);

let mut args = FluentArgs::new();
args.set("name", "Ada");
let welcome = localizer.format("welcome", &args)?;
assert_eq!(welcome, "Bienvenue, \u{2068}Ada\u{2069} !");
# Ok::<(), Box<dyn std::error::Error>>(())
```

The invisible Unicode isolation marks around variables prevent inserted text
from corrupting surrounding bidirectional text. Pass numbers as numbers so
Fluent can select locale-specific plural branches. Use `text` for a value with
no arguments, `format` for a value with arguments, and `attribute` or
`format_attribute` for compound messages such as button and accessibility
labels.

Formatting errors are returned as `TranslationError`; they do not silently fall
back and hide a broken translation. Missing values, messages, and attributes
also have distinct error variants, so applications can report faulty resources
during development and choose their own production policy.

## Apply writing direction

Use the negotiated locale for both copy and layout. This keeps text alignment,
anchored overlays, and keyboard navigation consistent:

```rust
# use argui::i18n::{Catalog, Localizer, langid};
use argui::ui::{Element, WritingDirection};
# let english = Catalog::parse(langid!("en-US"), "welcome = Welcome")?;
# let arabic = Catalog::parse(langid!("ar"), "welcome = مرحبًا")?;
# let mut localizer = Localizer::new(langid!("en-US"), [english, arabic])?;
# localizer.select([langid!("ar")]);

let direction = if localizer.is_rtl() {
    WritingDirection::Rtl
} else {
    WritingDirection::Ltr
};
let view = Element::column([
    Element::text(localizer.text("welcome")?),
]).direction_scope(direction);
# let _ = view;
# Ok::<(), Box<dyn std::error::Error>>(())
```

Collection widgets that expose an `rtl` option should receive the same
`localizer.is_rtl()` value for horizontal arrow-key behavior.

Keep `Localizer` in application model state when one model owns the locale. A
shared application can publish it through `ModelRuntime::register_service` and
read it with `Context::service`; changing the locale must still notify the model
so retained views that use translated copy are rebuilt.
